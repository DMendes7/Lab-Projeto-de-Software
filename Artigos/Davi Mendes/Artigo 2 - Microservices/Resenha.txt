Resenha do Artigo: Microservices
--------------------------------

Introdução
----------
O texto fala sobre arquitetura de microservices, q basicamente é dividir uma aplicação
grande (monolito) em varios serviços pequenos e independentes. Cada um cuida de uma parte
do sistema e se comunica com os outros por API ou mensageria.

Principais pontos
-----------------
- Cada serviço tem seu ciclo de vida proprio, pode ser atualizado separado.
- Escala só o q precisa, n precisa escalar o sistema inteiro.
- Equipes podem trabalhar de forma autonoma em serviços diferentes.
- Da pra usar tecnologias diferentes em cada serviço.
- Mas tbm traz desafios: integração mais complexa, monitoramento dificil, consistencia
de dados mais complicada.

Reflexão
--------
Microservices resolvem mtos problemas do monolito, mas criam outros novos.
É bom pra sistemas grandes, q precisam crescer rapido, mas pra projeto pequeno
o custo e complexidade n compensam.

Minha opinião
-------------
Achei legal pq explica pq empresas grandes tipo Netflix e Amazon usam isso.
Mas da pra ver q n é moda pra td, só faz sentido quando o sistema realmente
tem demanda e escala. Senão o monolito simples ainda é melhor.

Conclusão
---------
Microservices dao flexibilidade e autonomia, mas exigem maturidade e estrutura
pra funcionar direito.
